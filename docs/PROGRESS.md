# 一、已实现的功能点

## 触发方式

| 键 | 条件 | 行为 |
|---|---|---|
| `` ⌥` `` | 任何时候 | 解释光标所在的词/整行，**不用选中** |
| `` ` `` | 仅当有选中文本 | 解释选中的片段（没选中时照常打字，不影响 `` `include ``） |
| `` ⌥⇧` `` | 任何时候 | 直接开追问 |

没选中时用 `getWordRangeAtPosition` 取光标所在的词（正则带反引号，`` `uvm_info `` 能整个取到），
取不到退回整行。「不用选中也能问」是省交互成本的一半——选中本身就是最慢的一步。

## 三层回答，越靠前越快

| 层 | 实现 | 延迟 | 成本 |
|---|---|---|---|
| 1 本地词表 | `glossary.ts`，29 条手写 SV/UVM 构造 | **0ms** | 0 |
| 2 答案缓存 | `cache.ts`，globalState LRU 500 条，跨窗口跨会话 | **0ms** | 0 |
| 3 模型 | `llm.ts`，OpenAI 兼容端点 | ~1-2.5s | 约 $0.0004/次 |

词表匹配不是简单查表：归一化会剥掉 `#(...)` 参数化、`(...)` 实参、`::` 作用域和成员调用，
再按「整串 → 去实参 → 首 token → 首+次 token → 首+第三 token → 逐 token」的顺序试，
配一张结构关键字停用表（`if`/`for`/`function`/`input`…）避免语法骨架挡住真正想问的词，
外加一张别名表（`join_any`→fork 三兄弟、`vif`→virtual interface）和形状匹配
（`virtual my_if vif;` 命中 virtual interface，但 `virtual function ...` 不命中）。

29 条里有 15 条带一行**面试提示**，标出哪些属于「教材标准写法但真实工程不用」
（如 `program` block）。**只有词表带这一行，模型的答案永远不带**——原因见下。

## hover 展示

- 彩色：`<span style="color:var(--vscode-xxx);">`，用主题变量，亮暗主题自动跟随
- bullet 列表 + 按**视觉宽度**折行（汉字算 2，上限 72 ≈ 36 汉字）
- 不在 `` `代码` ``、`**粗体**`、`<span>` 标签中间断开
- 词条平均 6.6 行（重排前约 14 行），不用滚轮
- 底部一个「追问」入口（`isTrusted` 只白名单放行 `svPeek.ask` 这一个不收参数的命令）

## 追问

两种界面，`svPeek.askUi` 切换：

- **`inline`（默认）**：Comment Thread，嵌在代码行下方、自带输入框、**滚动不消失**。
  默认挂在那行的**上方**（`inlinePosition`），避免把「你问的那行」和「后面的逻辑」劈开。
  标题栏有「挪到侧边」按钮，一键把对话原样交给面板，代码立刻回原位。
- **`panel`**：右侧 webview，自绘 markdown（约 30 行，不引外部库），样式全走 `--vscode-*` 变量。

追问是多轮的，整段对话发回去模型才知道「它」指什么；追问的 token 上限自动放宽到 3 倍。
点 hover 的「追问」会把已经答过的内容带过去，不重复调模型。

## 上下文

`contextMode`：`auto`（默认，文件 ≤24000 字符就整个发）/ `file` / `window`。
**文件排在 prompt 最前面**，成为可缓存的稳定前缀——实测同一文件连问，
第二问起 91% 输入命中前缀缓存，续问反而比只发 ±20 行更便宜。

整文件模式下缓存 key 带「文件 uri + 内容指纹」，换文件或文件一改就失效。

## key 与部署

- key 三级回退：`svPeek.apiKey` > 环境变量（默认 `OPENAI_API_KEY`）> `svPeek.apiKeyFile`
  指向的 JSON 文件里的 `llm_api_key`。key 文件默认留空，留空就跳过这一级。
  几个工具共用一把 key 时都指向同一个文件，轮换时只改一处
- `"extensionKind": ["ui", "workspace"]`：Remote-SSH 窗口里仍跑在**本机**，
  才拿得到本机 key、走得通本机网络（同 GitHub Copilot 的做法）
- `npm run install-local` 一条命令打包 + 安装 + 覆盖
- 图标：`media/make-icon.py` 用 PIL 生成，对话气泡 + 数字方波

## 用户体感上的四件事（v0.3.0）

都是自己写出来的毛病，用起来才现形：

1. **按了键什么都不发生。** 光标停在空行/纯符号上时 `pickTarget` 返回 undefined，
   函数直接 return，一点提示都没有——分不清是没触发还是插件坏了。
   改成 `setStatusBarMessage(msg, 3000)`：非模态、3 秒自己消失。
   **不用 `showInformationMessage`**，那个要手动关，按一次错位置弹一个框，很吵。
2. **等模型那 2-3 秒是完全空白。** 弹窗要等答案回来才出现，感知上跟卡死一样，
   状态栏那个小转圈没人会去看。改成先弹一个「正在问模型…」占位，答案回来替换。
   **这依赖「hover 开着时再调一次 `showHover` 会刷新而不是关掉」**——留了
   `svPeek.showPending` 开关，万一某个版本行为不是这样，关掉就回旧行为，不用改代码。
3. **答得不好没有退路。** 词表和缓存给的是固定答案，再按多少次都一样。
   加「重问」（`svPeek.refresh`）：绕过词表和缓存直接问模型。
4. **key 没配好只能自己翻设置。** 报错的弹窗里加了「打开设置」和「重试」两个链接。

顺带把「答案回来时人已经走了」的判断收紧了：原来只查 `activeTextEditor` 没变，
现在还要求**光标仍在原来那个 range 里**（`stillThere()`）——
否则会在人家正在读的另一处代码上突然冒个弹窗出来。

新增的命令链接同样只白名单放行、**全都不收参数**，安全边界没松。

# 二、为什么是现在这样

## 这东西为什么存在

Cursor 自带 ⌘K/⌘L 就能解释代码。做这个的理由**不是答得更好，是交互成本**：

```
Cursor 聊天:  开面板 → 选中 → 打字说指令 → 等 → 侧栏读      ~8-10s
sv-peek:      点一下 → 敲一下 → 眼前                        ~1s / 词表命中 0s
```

省掉的最大一步是「**告诉 AI 我的指令是什么**」——读代码时那句指令永远是同一句，
每次重打就是纯浪费。指令写死在 prompt 里之后，还能顺手塞进 SV/UVM 专用的
system prompt 和面试视角，这是通用聊天面板给不了的。

接受这个边界：通用「解释代码」那部分是重复造轮子，**增量价值只在三处**——
词表的 0ms 响应、上下文送法调过、面试提示。

## 为什么是扩展，不是系统级弹窗

一开始的方案是 macOS 全局悬浮窗（NSPanel + 取选区）。砍掉了，因为读代码基本都在编辑器里，
而扩展把三块硬活全部消掉了：辅助功能权限、取选中文本（AX API / 合成 ⌘C）、
非抢焦点的窗口定位。工作量差 5-10 倍。

代价：覆盖不到 PDF / 网页 / Verdi 之类编辑器外的场景。以后真需要再单独做。

## 为什么用 hover，不自己画浮窗

VSCode / Cursor **没有**把任意内容放到光标处的公开 API。hover 是唯一的原生机制。
做法是把解释挂成某个 range 的 hover 内容，再程序化触发 `editor.action.showHover`
——它在**光标**处弹出，而光标刚好在你选中/点中的代码上。

**没有裸注册 hover provider 让它鼠标悬停自动触发**：鼠标每停一次打一次模型 =
烧钱 + 卡顿。必须快捷键显式触发，hover provider 只负责回读已经算好的内容。

## 为什么追问不用 hover 而是 Comment Thread

用户提了三件事，其中两件撞到同一堵墙：

1. hover 底部那行「模型名·耗时·token」对读代码的人没价值 → 删掉，
   降级成 `svPeek.showMeta` 开关（默认关），底部换成「追问」入口。
2. **滚轮一滑 hover 就没了，想让它留到点别处才关** → **做不到**。
   hover 的生命周期归编辑器的 ContentHoverWidget 管，滚动/移开鼠标/切焦点都会关，
   扩展只负责提供内容，没有 API 能改。`editor.hover.sticky` 只管「鼠标移进悬浮框不关」。
3. **想在下面加输入框追问** → hover 里也做不到，sanitizer 会把 `<input>`/`<textarea>` 剥掉。

2 和 3 指向同一个结论：**hover 不是那个容器**。于是加 `panel.ts`：单例 webview，
`ViewColumn.Beside`，常驻、可滚动、底部输入框、多轮对话。

分工：hover 做快速路径（词表 0ms，看一眼就走），面板做深聊。hover 底部的「追问」
链接把当前片段和已有答案带过去，所以开面板不会重复调一次模型。

### 那个 command 链接的安全边界

hover 里要放可点的 `command:` 链接就得开 `isTrusted`，但 hover 内容里混着模型输出。
折中：`isTrusted = { enabledCommands: ['svPeek.ask'] }` 只白名单放行这一个命令，
而且 **`svPeek.ask` 不收任何参数**——它只读当前编辑器的光标/选区。
所以哪怕模型真被注入、吐出一个这样的链接，最坏结果也只是打开追问面板。

### webview 里不引外部依赖

markdown 是自己渲染的（约 30 行）：输出格式是我们自己 prompt 规定的，
只要认 bullet、`**粗体**`、`` `行内代码` `` 三样就够，不值得为它引一个 markdown 库
再去对付 CSP。样式全用 `--vscode-*` CSS 变量，主题换了自动跟着换。

坑：`html()` 返回的是模板字符串，里面的 `\\*` 要到**运行时**才求值成 `\*`。
直接 grep 编译产物会以为正则写错了，得把模板求值出来再验。

## 内联框顶开代码怎么办

用户问「这样是不是挡住下面的代码了，要结合下文理解怎么办」。两个前提要先掰清楚：

- Comment Thread 是 **zone widget，顶开代码而不是盖住**，没有任何一行被遮住。
- **模型本来就看得到下文**：`contextMode: auto` 发的是整个文件。所以「答不准」不成立，
  真正的问题只是**人想同时看到答案和下文**。

三个办法叠加：

1. **默认挂在那行的上方**（`inlinePosition: above`，锚在 `startLine - 1`）。
   位移量两种挂法完全一样，区别在断层位置：挂下方会把「你问的那行」和「它后面的逻辑」
   劈成两半，而看懂一行往往正要接着看它下面几行；挂上方是
   「答案 → 那一行 → 后面的代码」连成一片。
2. **标题栏加「挪到侧边」按钮**（`svPeek.toSide`）：`thread.takeOver()` 把整个
   messages 交出来、收掉内联框，`panel.adopt()` 接管并重建显示用的 turns。
   对话历史不丢，代码立刻回到原位。
3. 折叠：Comment Thread 自带，点标题栏就收起来。

重建 turns 时要跳过两条不该显示的：`messages[1]`（塞了整个文件的那条 prompt）
和开场的自动提问 `AUTO_ASK`。这个常量提到 `prompt.ts` 让内联和面板两边共用。

## 「面试」提示为什么只由词表提供

每次都出现的提示等于没有提示——天天看到「面试」两个字，眼睛就自动跳过了，
真正该警觉的那几条反而被淹没。所以这一行必须稀缺。

**但这件事靠 prompt 管不住。** 三种写法依次试过，都失败：

| 写法 | 结果 |
|---|---|
| 软指令「不常考就不写这一行」 | 5 个片段里 4 个该省的没省 |
| 收紧标准 + 加一个「不该写」的反面示例 | 没改善，2/5 |
| 要求先认领「教材陷阱 / 反直觉」标签再写 | 它给 `$sformatf` 也贴了「反直觉」，2/5 |

第一版失败还有个具体原因：**唯一的 few-shot 示例里带着「面试：」**，模型照着模板抄。
但补了反面示例之后仍然不行——mini 模型会照模板填，然后给任何东西编个理由。

**结论：`不要写 X` 这种无条件禁令它执行得很好（改完 5/5 一行都不写），
`只在值得时写 X` 这种条件判断它执行不了。** 管不住的就别交给 prompt 管。

最终方案：
- 模型 prompt 里明令不要写这一行；`extension.ts` 再无条件丢弃任何漏网的「面试：」行
  （双保险，而且不让它退化成一条普通要点）
- 面试提示只由**人工挑过的词表**提供。顺手删了两条水分大的：
  `interface`（跟 `virtual interface` 那条高度重复）、`always_comb`（「常跟 X 一起问」没有具体内容）
- 开关 `svPeek.interviewLine` 只管词表那一行
- 想要模型的面试角度？**在追问里直接问一句**——用户主动要的，本来就 100% 有信号

## 整文件上下文和前缀缓存

OpenAI 对 **≥1024 token 的 prompt 前缀**自动缓存。`system + 文件正文` 是逐字不变的前缀，
把变化的问题写在最后，同一个文件连问多处时从第二问起就走缓存。顺序反过来，一次都命中不了。

实测（13284 字符 / 430 行的模拟文件，跟一个中等 UVM env 文件差不多）：

| | 入 tok | 其中缓存 | 出 tok | 延迟 |
|---|---|---|---|---|
| 窗口 ±20 行 | 892 | 0 | 66 | 1.2s |
| 整文件，首问 | 4214 | 0 | 55 | 0.9s |
| 同文件，之后每问 | 4215 | **3840（91%）** | ~55 | 1.0s |

**前缀太小缓存不生效**：2672 字符的 demo.sv（共享前缀约 1250 token）实测 `cached_tokens` 一直是 0，
刚过 1024 门槛不够用。堆到 2900 token 以上就稳定 95% 命中。真实 SV 文件都在这个量级之上。

### 折算成钱

按 mini 级价格量级（$0.25/M 输入、缓存输入约 1/10、$2/M 输出）：

| | 单次 | $5 能问 |
|---|---|---|
| 窗口模式 | $0.00036 | 约 14000 次 |
| 整文件·首问 | $0.00116 | 约 4300 次 |
| 整文件·续问 | $0.00030 | 约 16600 次 |
| 实际混合（一个文件问 10 处） | $0.00039 | **约 13000 次** |

结论：**首问贵 3.3 倍，但同一文件的续问比窗口模式还便宜**（输出 token 更贵，而两种模式输出一样短）。
混合下来基本持平。缓存输入的确切折扣没核对过，以 OpenAI 定价页为准。

**缓存有过期**：几分钟不碰同一前缀就失效。一个文件只问一处就走人的话，每次都是首问价。

## 成本和模型选型（实测 2026-09-11）

同一个片段（`seq_item_port`，636 prompt tokens）打三个模型：

| 模型 | 延迟 | completion tokens | 答案质量 |
|---|---|---|---|
| **gpt-5.4-mini** | 2625ms | 153 | 最好。点破了真正的坑（漏 `item_done` 会卡住），面试点具体到 `get_next_item` vs `get` |
| gpt-4.1-mini | 1830ms | 120 | 空话多（"提升模块化和复用性"），正是 prompt 里明令禁止的那种 |
| gpt-4o-mini | 1758ms | 158 | 同上，更啰嗦 |

**结论：默认留 gpt-5.4-mini。** 快 0.8s 换一个明显更水的答案不划算，
而且真正高频的构造本来就走词表 0ms，模型只兜底长尾。

改成 bullet 格式后再测：**789 入 / 84 出**（system prompt 变长了，但输出短了一半，
而输出 token 更贵，净下来更省）。格式遵守得很好，4 条短 bullet + 一行面试。

单次成本（旧版格式）：636 入 + 153 出。按 mini 级价格量级（$0.25/M 入 + $2/M 出）≈ **$0.0005/次**，
**$5 约一万次**。`gpt-5.4-mini` 确切单价没核对过，以 OpenAI 定价页为准。

**注意：早期文档里写的「~1s」是错的**，实测 2.6s。

## 为什么不流式

hover 内容是快照，边流边刷会闪。改成把答案**限死 2-4 行**（`max_completion_tokens` 约 250），
非流式 ~1s 就够。想看长的，以后在 hover 里放 command link 开侧边 webview。

## 「先弹占位再替换」这条路走死了（2026-09-13）

v0.3.0 加了「问模型时先弹一个『正在问模型…』，答案回来替换」。**是个倒退，v0.5.1 默认关掉了。**

原因：**VSCode 1.85 没有关闭 hover 的命令**（翻过 workbench bundle，hover 相关只有
`showHover`、`showDefinitionPreviewHover` 和一堆 `scroll*Hover`，没有 hide/close）。
hover 一旦开着，再调一次 `showHover` 是空操作，内容不会重画。
结果：用户盯着一个**永远转圈的旧画面**，而请求其实 1 秒就回来了——
比「等 1 秒什么都没有」糟糕得多，直接被当成卡死。

真实数据（一次 Remote-SSH 窗口里的日志）：

```
弹出「正在问模型」        +2ms
→ POST                   body=3983 字符
← 响应头                 1532ms  HTTP 200
模型返回  入 1454（缓存 1280）出 63
渲染完成                 +1540ms      ← 这里就结束了，但画面没变
```

**教训：任何「先占位后替换」的交互，都要先确认那个容器支持刷新。**
hover 不支持。要做这种交互只能换容器（内联 Comment Thread 和 webview 面板都支持，
它们的「思考中…」就是这么做的，工作正常）。

顺带：等待期间唯一会动的东西是状态栏那行 `withProgress`，
给它加上了片段名（`正在解释 uvm_config_db…`），至少知道在等谁。

## 扩展可能实际跑在远程侧（2026-09-13，可接受）

Remote-SSH 窗口里日志第一行是 `remoteName=ssh-remote`。`vscode.env.remoteName` **只在 workspace
扩展宿主里有值**，所以尽管 manifest 声明了 `extensionKind: ["ui","workspace"]`，
用户设置里也加了 `remote.extensionKind: {"local.sv-peek": ["ui"]}`，
它**还是跑在远程服务器上**。多半是 VSCode 连远程时把它一并装进了远程的扩展目录，
装在哪就在哪跑。

**结论：不改。** 能用而且不慢（远程到 api.openai.com 是 0.9-1.5s）。

两个后果：

1. 环境变量和 key 文件读的都是**远程那台机器上的**，key 得放在远程。
   放之前先确认那台机器不是多人共用的。
2. 答案缓存存在远程的 globalState 里，和本地窗口的是两份，互不复用。
   代价只是同一个片段在两边各问一次，不值得为它折腾。

真要改成跑本地：远程窗口的扩展面板里找到「SSH: xxx — 已安装」那栏下的 SV Peek，
只卸载那一份，本地那份保留。

## `` ⌥` `` 的死键风险，和用户级键绑定这道保险（2026-09-13）

真机上出过事：Remote-SSH 窗口里扩展没接管那一下，`` ⌥` `` **直接落进编辑器改了代码**——
它在 macOS 上是死键（输入重音符），当时有选中文本，选区被整个替换。

一度换成 `` ⌘` ``（带 `⌘`/`⌃` 的组合永远不会插入文本，失败时最坏只是没反应），
但 `` ⌘` `` 被 macOS 系统占着「App 内窗口切换」，而且 `⌘⌥` 组合难按，
最终**改回 `` ⌥` ``**。

改回去的同时加了一道保险：**把同样的键绑定也写进用户自己的 `keybindings.json`**。
用户级绑定由 VSCode 本体注册，跟扩展有没有加载无关——扩展没跑起来的窗口里，
这个键会被「吃掉」（顶多提示命令找不到）而不是落进编辑器。
和扩展 manifest 里的重复是故意的，别当成冗余删掉。

扩展没法替用户写这一份，README 里写了建议。**换机器也要把这份用户级绑定带过去**，
否则又回到「失败时毁数据」。

## 为什么 `` ` `` 键不用双击

原始想法是双击反引号。问题：VSCode 原生 keybinding 只有单键和 chord，
写成 chord `` ` `` `` ` `` 会**吞掉第一下**——`` `include `` 直接打不出来。
而 SV 的所有编译器指令和 UVM 宏都以反引号开头，这个代价不能接受。

改成单击 + `when: editorHasSelection` 的门：没选中时照常打字，有选中才抢键。
比双击还少一下，且零冲突（除了「选中后想打反引号替换」，SV 里不存在这种写法）。

## 为什么不选中也能问

选中本身就是最慢的一步（拖鼠标或 shift+方向）。`pickTarget()` 在没选中时
用 `getWordRangeAtPosition` 取光标所在的词，取不到退回整行。
交互压到「点一下 → 敲一下」。

## 文档一改就丢缓存

`onDidChangeTextDocument` 里直接 `notes.delete(整篇)`。存下来的 range 编辑后就对不上了，
与其做 range 平移不如整篇丢掉——这工具是**读**代码用的，正常使用不会触发。

## hover 怎么上色

VSCode 的 markdown sanitizer 只放行 `<span>` 上的 `color` / `background-color`，
值必须匹配这条正则（实测 1.85 的 bundle）：

```
/^(color\:(#[0-9a-fA-F]+|var\(--vscode(-[a-zA-Z]+)+\));)?(background-color\:...)?$/
```

两个坑：**`color:` 后面不能有空格，结尾必须有分号**，否则整条 style 被丢掉；
**var 名里不能有数字**（`--vscode-charts-blue` 行，带数字的不行）。
用主题变量而不是写死色值，亮/暗主题都能跟着走。需要 `markdownString.supportHtml = true`。

`class` 属性只放行 codicon，别指望自定义 class。

## hover 怎么控宽度

hover 窗口横向撑到最长那一行，长句会把它拉得很宽，眼睛要横着扫。
`render.ts` 按**视觉宽度**折行（汉字算 2、ASCII 算 1），上限 54 ≈ 27 个汉字。

两条硬约束：
- `` `代码` ``、`` ``代码`` ``、`**粗体**` 是原子块，从中间断开 markdown 就废了，
  会把标记原样显示出来。双反引号必须排在单反引号前面匹配。
- 断点要**回退到超宽前的最后一个标点**，不能「超宽后再找下一个标点」——
  后者会让「标点很久才出现」的句子一路拖长。这是第一版的 bug。

词表的 `body: string` 因此改成了 `bullets: string[]`：整段长句折出来是一坨，
短 bullet 才读得舒服。

## Remote-SSH 为什么要声明 extensionKind

默认会跑错地方。没声明 `extensionKind` 的扩展，VSCode 在 Remote-SSH 窗口里
会把它装到**远程服务器**的 workspace 扩展宿主里，那样同时坏两件事：
读的是远程的家目录和环境变量（拿不到本机的 key 文件），
而且远程服务器未必连得上 api.openai.com。

修法：`"extensionKind": ["ui", "workspace"]`，`ui` 在前 = 优先跑在本机这一侧。
**GitHub Copilot 用的就是这个声明**，场景完全一样（需要本机网络和本机凭据，
但要编辑远程文件）。文档内容照样读得到——document model 在本地渲染进程里，
跟文件实际存在哪无关；UI 扩展拿不到的是远程**文件系统**（node `fs` 那条路），
而我们只用 `fs` 读本机的 key 文件，正好对。

`vscode.env.remoteName` 只在 workspace 扩展宿主里有值，拿它做兜底提示：
真被装到远程去了，报 key 错误时直接告诉用户去卸载远程那一侧。

真机上的结果见上面「扩展可能实际跑在远程侧」那节：声明了也可能照样跑在远程。

## 打包发布

`npm run install-local` 一条命令搞定打包 + 安装 + 覆盖。产物约 50KB，16 个文件。
装好是 `local.sv-peek`，重载窗口后所有工程都生效，不用再按 F5。

vsce 打包踩的坑：
- `"private": true` 会被直接拒绝，要删掉。
- README 里的相对链接（`[x](docs/PROGRESS.md)`）在 `package.json` 没写 `repository` 时报错，
  因为它要把链接改写成仓库 URL。没写 `repository` 就把链接改成纯路径。
- 没写 `repository` 时 vsce 还会问一句 `Do you want to continue? [y/N]`；
  stdout 不是终端（比如在脚本里跑）时它自动当 `y`。
- `.vscodeignore` 要排掉 `src/`、`tests/`、`docs/`、`**/*.ts`、`**/*.map`，
  只留 `out/` 和 `samples/`。

没发到 Marketplace——那需要 publisher 账号和 Azure DevOps PAT。
分发方式是 GitHub Releases 上的 `.vsix` 文件。

# 三、踩过的坑

- `Range.intersection()` 对「刚好挨着」的两个 range 返回的是**空 range 而不是 undefined**，
  直接判真假会把相邻的旧解释误删。要额外判 `isEmpty`。
- `strict` 下 `arr[0]` 是 `string | undefined`，`toks[0].startsWith(...)` 编译不过。
  先 `const first = toks[0]; if (first)` 再用。
- **模型返回空内容**最常见的原因是 `max_completion_tokens` 被推理 token 吃光，
  `llm.ts` 里把 `finish_reason` 一起报出来，否则这个错完全没线索。
- 同时装了 Cursor 之类 VSCode 系编辑器的机器上，`code` 命令可能指向的不是 VSCode，
  `code --install-extension` 就装进别的编辑器去了。装之前先 `which code` 看一眼。

## 复查第一轮修掉的

1. **（安全）模型输出被塞进 `isTrusted = true` 的 MarkdownString。**
   trusted markdown 里 `command:` 链接是可点的。模型读的是不可信的代码文件，
   被注入一句 `[点我](command:...)` 就能变成可点的命令。改成 `isTrusted = false`。
   以后要加 command link，用 `{ enabledCommands: ['svPeek.xxx'] }` 精确放行，别开全量。
2. **连按两次快捷键时，可能谁也看不到结果。** 原来 `inFlight` 存的是 key，
   第二次直接 return；万一第一次的请求回来时用户已经切走，那次就什么都不渲染。
   改成存 promise，后来的调用等同一个结果、在自己的编辑器里渲染。
3. **缓存每次读都把整个 store 回写磁盘**（500 条）。LRU 时间戳不需要这个精度，
   改成超过 1 小时才回写。
4. **词表候选被结构关键字挡住。** 选中整行 `if (!uvm_config_db#(...)::get(...))`
   时首 token 是 `if`，漏掉真正想问的词。加了结构关键字停用表，逐个 token 兜底。

## 复查第二轮修掉的

5. **折行断在 `<span style="...">` 标签中间。** style 属性里有分号，而分号是断点字符，
   一断 HTML 就废了，标记原样显示出来。修法：span 标签当原子块，且**视觉宽度记 0**
   ——它是标记不是内容，算进宽度会让真正的文字被挤掉。

## 复查了但故意没改的

- ~~缓存 key 不含上下文~~ **已改**：整文件模式下 key 带上
  `文件 uri + 内容指纹`，换文件或文件一改就失效；窗口模式仍用全局 key，
  让常见片段跨文件复用。
- **`fetch` 在扩展宿主里的可用性**：VSCode 1.85 是 Electron 25 / Node 18，全局 `fetch` 应该有。
  独立脚本验过 API 本身，打包安装后扩展内也真机发过请求。真炸了就退回 `https` 模块。
